# Пакетный режим Конфигуратора 1С 8.3.27

**Фактические тесты выполнены только на Windows. Варианты macOS и Linux подготовлены, но на этих ОС не тестировались.**

Сначала определи ОС и прочитай [платформенные правила](references/platforms.md).

## Источник истины

Используй только файлы этого скилла. Сначала открой [индекс операций](references/00-index.md), затем только справочники, указанные для нужной операции. Не читай все справочники без необходимости. Рабочие справочники `00`-`11` включены в этот skill; внешнего проектного каталога документации не требуется.

Если требуемая команда, ключ, сочетание параметров или поведение не подтверждены в справочниках, ответь: `Операция не подтверждена документацией скилла` и не придумывай команду.

## Область применения

Скилл покрывает:

- запуск `Designer (1cv8.exe/1cv8)` для 8.3.27;
- полную и инкрементальную XML-выгрузку;
- полную и частичную XML-загрузку;
- выгрузку и загрузку бинарных конфигураций через `DumpCfg` и `LoadCfg`;
- управляемое объединение через `MergeCfg` и XML-файл настроек;
- основную конфигурацию, одно расширение и все расширения там, где это документировано;
- подключение, получение, захват, помещение и отмену захвата в хранилище;
- обновление конфигурации базы данных;
- проверки модулей, конфигурации и применимости расширения;
- `/Out`, `/DumpResult`, код процесса и фактический результат.

## Обязательный алгоритм

1. Определи версию платформы. Если она не 8.3.27, не применяй синтаксис этого скилла как гарантированно верный.
2. Определи цель: основная конфигурация, одно расширение или все расширения.
3. Определи одну пакетную операцию. Комбинируй команды только когда это явно разрешено в `references/06-update-db-cfg.md`.
4. Открой релевантные справочники по `references/00-index.md`.
5. Проверь обязательные входы: путь к `1cv8.exe`, `/F` или `/S`, аутентификацию, пути файлов, имя расширения, реквизиты хранилища.
6. Проверь несовместимые и опасные параметры.
7. Сформируй команду для одной оболочки: PowerShell/cmd.exe на Windows или Bash/Zsh на Unix.
   Не смешивай правила переноса строк; см. платформенные правила.
8. Для безоператорного запуска используй `/DisableStartupDialogs`, `/DisableStartupMessages`,
   отдельные файлы `/Out` и `/DumpResult`. Не запускай несколько Designer одновременно для одной базы.
   Запиши команду без секретов, время и PID; дождись завершения именно своего процесса.
9. Перед запуском создай все родительские каталоги полных путей.
10. Не очищай рабочие выгрузки или чужие журналы. После запуска проверь код процесса, `/DumpResult`, `/Out` и фактический результат. Не объявляй успех только по одному признаку.

## Строгие запреты

- Не совмещай `-Extension` и `-AllExtensions`.
- Не применяй XML-ключ `-update` к операциям хранилища.
- Не считай `-Objects` автоматическим поиском изменений.
- Не подменяй файл объектов хранилища списком XML-путей.
- Не используй `ConfigurationRepositoryUnbindCfg` для проверки подключения.
- Не загружай XML основной конфигурации в расширение или наоборот.
- Не выполняй полную `LoadConfigFromFiles -Extension` для расширения, подключенного к хранилищу.
- Не совмещай `-AllExtensions` с `-files` или `-listFile` при XML-загрузке.
- Не указывай одновременно `-files` и `-listFile`.
- Не выполняй частичную XML-загрузку без явного `-Format Plain` или `-Format Hierarchical`.
- Не создавай `ConfigDumpInfo.xml` вручную.
- Не выполняй `MergeCfg` без заранее проверенного файла `-Settings`.
- Не считай `Configuration/DoNotMerge` достаточным ограничением состава donor: явно задай
  `DoNotMerge` для каждого вспомогательного объекта donor.
- Не добавляй к `MergeCfg` параметры поддержки без определения фактического режима поддержки.
- Не распространяй код `101` на команды, для которых он не документирован.
- Не копируй Unicode-тире вместо ASCII-дефиса в ключах командной строки.

## Опасные параметры

Используй только при явном разрешении пользователя и после объяснения последствия:

- `ConfigurationRepositoryBindCfg -forceReplaceCfg`: подтверждает замену непустой конфигурации содержимым хранилища;
- `ConfigurationRepositoryUnLock -force`: локальные изменения будут потеряны;
- `UpdateDBCfg -SessionTerminate force`: активные сеансы могут быть принудительно завершены;
- `DumpConfigToFiles -update -force`: при несовпадении версии формата будет выполнена полная выгрузка;
- `LoadConfigFromFiles -NoCheck`: проверка целостности отключается;
- `ConfigurationRepositoryCommit -force`: выполняется попытка удалить ссылки на удаленные объекты.
- `MergeCfg -force`: объединение продолжается при определенных предупреждениях.
- `MergeCfg -ClearUnresolvedRefs`: неразрешенные ссылки очищаются.
- `MergeCfg -IncludeObjectsByUnresolvedRefs`: состав объединения автоматически расширяется.

## Формат ответа

При формировании команды выдай:

1. сценарий;
2. подтвержденные предусловия;
3. команду;
4. назначение только использованных ключей;
5. ожидаемый результат;
6. способ проверки;
7. действие при ошибке.

Если данных недостаточно, используй заметные заполнители `<...>`. Не выдумывай путь, пароль, имя базы, расширения или объекта.

## Подключение и права

Skill самодостаточен для справки по пакетному режиму и не зависит от `1c-add-new-object`.
Пути, подключение базы и аутентификация задаются для текущей задачи. Примеры не являются
готовыми настройками пользователя. Соблюдай ограничения проекта, включая запрещённые проверки
и правила хранилища. Запрос на формирование команды не разрешает её выполнение.

## Выполнение

Если пользователь просит только команду, не запускай ее.

Если пользователь просит выполнить операцию и среда доступна:

1. проверь предусловия;
2. выполни команду;
3. прочитай `/Out` и `/DumpResult`;
4. проверь фактический результат;
5. останови цепочку при ошибке;
6. сообщи точный результат без вымышленного текста ошибки.

Для поиска используй `scripts/search-docs.ps1` на Windows или `scripts/search-docs.py` через Python.
Проверка: `scripts/validate-skill.ps1` либо `scripts/validate-skill.py`. Unix-варианты не тестировались на своих ОС.
