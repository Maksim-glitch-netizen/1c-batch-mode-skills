# Подключение и получение из хранилища

## Реквизиты доступа

```text
/ConfigurationRepositoryF <каталог-хранилища>
/ConfigurationRepositoryN <пользователь>
/ConfigurationRepositoryP <пароль>
```

Эти параметры можно комбинировать с командами операций хранилища.

## Подключение

```text
/ConfigurationRepositoryBindCfg
    [-forceBindAlreadyBindedUser]
    [-forceReplaceCfg]
    [-Extension <имя-расширения>]
```

- Без `-Extension`: основная конфигурация.
- С `-Extension`: указанное расширение.
- `-forceBindAlreadyBindedUser`: выполняет подключение, даже если данный пользователь уже имеет конфигурацию, подключенную к этому хранилищу.
- `-forceReplaceCfg`: подтверждает замену непустой конфигурации конфигурацией из хранилища. Использовать только при явном разрешении.

## Получение

```text
/ConfigurationRepositoryUpdateCfg
    [-v <номер-версии>]
    [-revised]
    [-force]
    [-Objects <xml-файл-списка-объектов>]
    [-Extension <имя-расширения>]
```

- Без `-Extension`: основная конфигурация.
- С `-Extension`: хранилище указанного расширения.
- Если `-v` отсутствует или равен `-1`, документирована загрузка последней версии.
- `-revised`: получать захваченные объекты, когда требуется; для неподключенной конфигурации игнорируется.
- `-force`: подтверждает получение новых объектов и удаление существующих объектов. Без него эти действия пропускаются.
- `-Objects`: ограничивает операцию объектами из официального XML-файла списка объектов. Без параметра участвует полная конфигурация.

В английской странице 8.3.27 описание поведения `-v` для неподключенной конфигурации содержит противоречивые фразы. Скилл не должен выводить из них дополнительное правило. Для надежной работы сначала подключи конфигурацию через `ConfigurationRepositoryBindCfg`, а `-v` используй только для явно требуемой версии.

## Инкрементальность

У `ConfigurationRepositoryUpdateCfg` нет документированного ключа `-update`.

- Без `-Objects` операция относится к полной конфигурации.
- С `-Objects` операция относится только к заранее указанным объектам.
- `-Objects` не ищет измененные объекты автоматически.

## Проверка подключения

В официальном перечне команд 8.3.27 нет отдельной недеструктивной команды, которая возвращает булево состояние подключения основной конфигурации или расширения к хранилищу.

Не используй для проверки:

- `ConfigurationRepositoryUnbindCfg`, потому что команда изменяет состояние;
- наличие реквизитов `ConfigurationRepositoryF/N/P`, потому что они подтверждают только переданные параметры;
- существование расширения, потому что оно не подтверждает подключение к хранилищу.

Допустимые подходы:

1. проверить состояние интерактивно в Конфигураторе;
2. хранить подтвержденный факт успешного `ConfigurationRepositoryBindCfg` в состоянии среды;
3. выполнить требуемую операцию и анализировать фактический `/Out`, не придумывая универсальный текст ошибки.
