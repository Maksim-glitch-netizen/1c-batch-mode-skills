# XML-выгрузка: `/DumpConfigToFiles`

## Документированный синтаксис

```text
/DumpConfigToFiles <каталог>
    [-Format Plain|Hierarchical]
    [-Extension <имя>]
    [-AllExtensions]
    [-update]
    [-force]
    [-getChanges <файл>]
    [-configDumpInfoForChanges <файл-ConfigDumpInfo.xml>]
    [-listFile <файл-списка-объектов>]
    [-configDumpInfoOnly]
    [-Server [-JobsCount <число>]]
    [-Archive <zip-файл>]
    [-ignoreUnresolvedReferences]
```

## Полная выгрузка

Основная конфигурация:

```text
/DumpConfigToFiles "C:\work\xml\main" -Format Hierarchical
```

Одно расширение:

```text
/DumpConfigToFiles "C:\work\xml\extension" -Format Hierarchical -Extension "ExtensionName"
```

Все расширения:

```text
/DumpConfigToFiles "C:\work\xml\extensions" -AllExtensions
```

- `Plain`: линейный формат.
- `Hierarchical`: иерархический формат, используется по умолчанию.
- `-AllExtensions`: выгружает расширения без основной конфигурации; каждое расширение помещается в собственный подкаталог.

## Инкрементальная выгрузка

```text
/DumpConfigToFiles "C:\work\xml\main" -update
```

`-update` выгружает объекты, версии которых отличаются от предыдущей выгрузки. Платформа берет `ConfigDumpInfo.xml` из текущего каталога выгрузки и после успешной операции обновляет его.

Если `ConfigDumpInfo.xml` отсутствует или версия формата не совпадает, формируется ошибка.

Используй `-update` только если:

- каталог является предыдущей выгрузкой той же конфигурации или того же расширения;
- файл `ConfigDumpInfo.xml` существует;
- формат выгрузки не менялся;
- предыдущая операция завершилась корректно;
- каталог не смешивался с другой выгрузкой.

Не используй `-update` для первой, чистой или неподтвержденной выгрузки.

## `-force`

`-force` применяется только вместе с `-update`. При несовпадении версии формата платформа выполняет полную выгрузку. Без `-update` параметр игнорируется.

## Список изменений

```text
/DumpConfigToFiles "C:\work\xml\main" -update -getChanges "C:\work\logs\changes.txt"
```

`-getChanges` записывает отличия текущей конфигурации относительно файла версий.

`-configDumpInfoForChanges <полный-путь>` задает отдельный `ConfigDumpInfo.xml` для сравнения и применяется только вместе с `-update` и `-getChanges`. Указанный файл сравнения не обновляется.

## Контрольная выгрузка после изменения

После `MergeCfg` или XML-загрузки используй `DumpConfigToFiles -update` без `-getChanges`,
если каталог является корректной предыдущей выгрузкой той же конфигурации. Успешный файл
сравнения не доказывает обновление XML. Проверь время изменения `Configuration.xml` и
`ConfigDumpInfo.xml`, ожидаемый XML объекта и запись объекта в составе конфигурации.
Не удаляй предыдущие выгрузки ради полного запуска.

## `-listFile`

Параметр задает файл со списком объектов, которые выгружаются независимо от статуса обновления. Официальная документация 8.3.27 прямо указывает: `-listFile` нельзя использовать с другими параметрами этой команды.

Строгое правило скилла: при `-listFile` не добавляй другие необязательные параметры, включая `-update`, `-force`, `-getChanges`, `-Extension`, `-AllExtensions`, `-Server` и `-Archive`. Если нужен не описанный сочетанием сценарий, остановись и запроси подтвержденный источник.

## `-configDumpInfoOnly`

Создает только `ConfigDumpInfo.xml`. Может сочетаться только с `-Format`. По умолчанию создается файл для иерархического формата.

## Сервер и архив

- `-Server`: выгрузка выполняется на сервере 1С в многопоточном режиме; имеет смысл для клиент-серверной базы.
- `-JobsCount`: число параллельных фоновых заданий; значение по умолчанию `0`, платформа определяет число автоматически.
- `-Archive <файл>`: выгрузка в ZIP-архив.
- `-ignoreUnresolvedReferences`: пропускает документированные недоступные ссылки; эта опция может привести к отличиям после обратной загрузки, поэтому не добавляй ее автоматически.
