# ОС и оболочка

**Фактические тесты выполнены только на Windows. macOS и Linux подготовлены, но на своих ОС не тестировались.**

## Windows

Используй Windows PowerShell 5.1/7 или cmd.exe по `01-common-cli.md` и `08-results-errors.md`.
`1cv8.exe` и пути с обратными слешами в справочниках - Windows-примеры.
Для проверок доступен `scripts/validate-skill.ps1`, для поиска - `scripts/search-docs.ps1`.

## macOS и Linux

Для локального поиска и проверки достаточно Python 3.10+:

```bash
python3 -B '<skill>/scripts/search-docs.py' MergeCfg
python3 -B '<skill>/scripts/validate-skill.py'
```

Используй фактический исполняемый файл Designer 8.3.27, найденный на целевой машине, абсолютные
пути ОС с `/` и точный регистр имён файлов. Не добавляй суффикс `.exe` к Unix-бинарному файлу.
Пути вида `C:\work` и команды cmd.exe не являются Unix-командами. Не угадывай расположение .app
на macOS или каталога платформы в Linux. Проверь архитектуру и доступность режима DESIGNER.
Наличие GUI-библиотек, дисплея и лицензии проверяется отдельно; запуск на headless-системе этим
комплектом не подтверждён. Автоматической настройки X11, Wine, Rosetta или контейнеров нет.

В Bash/Zsh для переноса строки используется `\`, в PowerShell - обратная кавычка, в cmd.exe - `^`.
Не смешивай их. Для `/S` используй заключённое в кавычки `server/infobase` либо документированную
для установленной платформы форму. Не применяй Windows-аутентификацию `/WA+` автоматически:
подтверди способ входа для целевой платформы и пользователя.

Ниже только Bash-шаблон, не проверенный Unix-рецепт. Заполни значения, согласуй аутентификацию и
сначала проверь среду на разрешённой тестовой базе. Команда использует документированные ключи
8.3.27; фактическая применимость должна быть проверена на целевой ОС.

```bash
one_c='<absolute-path-to-Designer>'
target_db='<absolute-path-to-file-infobase>'
main_source='<absolute-path-to-XML-directory>'
log_file='<absolute-path-to-new-log>'
result_file='<absolute-path-to-new-result>'
connection=( /F "$target_db" )
# Задай разрешённую аутентификацию. /WA- отключает вход средствами ОС, но не задаёт пользователя.
auth=( /WA- )
"$one_c" DESIGNER "${connection[@]}" "${auth[@]}" \
  /DisableStartupDialogs /DisableStartupMessages \
  /Out "$log_file" /DumpResult "$result_file" \
  /DumpConfigToFiles "$main_source"
exit_code=$?
```

Пустые/фиктивные значения в угловых скобках не передаются 1С. Сохрани `exit_code`, прочитай
числовой `/DumpResult`, полный `/Out` и проверь XML-файлы. Нулевой код не заменяет эти проверки.
Существующий журнал не удаляется; каждому запуску назначаются новые файлы.

Для LoadConfigFromFiles, DumpCfg и MergeCfg сохраняй состав ключей соответствующего справочника,
меняй только оболочку, пути и согласованное подключение. Подготовка Unix-шаблона не делает его
проверенным рецептом. При неподтверждённой особенности установленной платформы останови запуск.

Официальные источники: [руководство 1С 8.3.27](10-source-register.md) и
[руководство 1С о платформах и компонентах](https://1c-dn.com/library/tutorials/1c_enterprise_development_tools_user_guide/).
Они не заменяют тест именно этой поставки на macOS/Linux.
