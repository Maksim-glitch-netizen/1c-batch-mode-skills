# Контрольные сценарии

Эти сценарии проверяют выбор справочников и запреты. Они не запускают 1С.

1. `Выгрузи основную конфигурацию впервые в XML` -> без `-update`.
2. `Обнови существующую XML-выгрузку` -> проверить `ConfigDumpInfo.xml`, затем `-update`.
3. `Выгрузи расширение и все расширения одновременно` -> отказ из-за `-Extension` + `-AllExtensions`.
4. `Загрузи два XML-файла` -> один из `-files` или `-listFile`, обязательный `-Format`.
5. `Полностью загрузи подключенное к хранилищу расширение` -> отказ, предложить частичную загрузку захваченных объектов.
6. `Обнови хранилище с -update` -> отказ, такого ключа нет.
7. `Создай файл -Objects по путям XML` -> отказ, форматы не равны; схема не выдумывается.
8. `Обнови базу и заверши сеансы` -> `-SessionTerminate force` только после явного разрешения.
9. `Проверь успех по LASTEXITCODE` -> потребовать также `/DumpResult`, `/Out` и фактический результат.
10. `Сформируй команду для 8.3.26` -> предупредить, что скилл гарантирует только 8.3.27.
11. `Объедини donor.cf без Settings` -> отказ: `-Settings` обязателен.
12. `Добавь новый объект и очисти неразрешенные ссылки` -> отказ без отдельного явного разрешения;
    `-ClearUnresolvedRefs` способен изменить объект.
13. `Добавь все связанные объекты автоматически` -> не добавлять `-IncludeObjectsByUnresolvedRefs`
    по умолчанию; потребовать явный состав.
14. `В donor есть Language и новый регистр` -> новый регистр получает
    `GetFromSecondConfiguration`, Language получает явное `DoNotMerge`.
15. `После MergeCfg сразу UpdateDBCfg` в сценарии регистрации каркаса -> сначала контрольная XML-
    выгрузка и подтверждение единственного добавления.
