# Инструмент `new_object_workflow.py`

Скрипт использует только стандартную библиотеку Python и не запускает 1С.

## Поддерживаемые команды

### `prepare`

Обязательные аргументы:

- `--type` - канонический тип метаданных `meta-compile`;
- `--name` - имя объекта 1С;
- `--baseline-configuration` - свежий `Configuration.xml` основной конфигурации;
- `--workspace` - новый пустой каталог внутри папки задачи.

Создает manifest, минимальный JSON объекта и каталоги артефактов. Проверяет отсутствие объекта в
baseline и сохраняет отдельный снимок `baseline\Configuration.xml`, который не зависит от
последующих выгрузок в исходный каталог. SHA-256 снимка хранится в manifest и проверяется командами
`finalize` и `verify-main`. Для `AccumulationRegister` JSON является массивом из целевого регистра и donor-only
документа-регистратора; имя документа вычисляется детерминированно из полного имени регистра.
Целевой регистр получает технические измерение и ресурс, перечисленные в manifest как
`bootstrapMembersToReplace`.

### `finalize`

Аргумент `--manifest` указывает manifest подготовленного workspace. Команда требует уже созданный
`donor-src\Configuration.xml`. Она проверяет наличие целевого объекта и формирует окончательные:

- `artifacts\MergeSettings.xml`;
- `artifacts\donor-objects.json`.

Все нецелевые корневые объекты donor получают `DoNotMerge`.

### `verify-main`

Аргументы:

- `--manifest` - manifest;
- `--current-source` - корень повторно выгруженной основной конфигурации.

Команда проверяет единственность добавления и ожидаемый XML-файл объекта.

### `verify-ready`

Аргументы совпадают с `verify-main`. Команда запускается после разработки объекта и перед финальным
`UpdateDBCfg`. Она запрещает продолжение, пока в объекте остаются технические элементы из
`bootstrapMembersToReplace`. Для регистра накопления дополнительно требуется хотя бы один реальный
документ, в `RegisterRecords` которого присутствует полное имя нового регистра.

## Поддерживаемые типы

Список синхронизирован с `meta-compile`: справочники, документы, перечисления, константы, регистры,
планы видов, бизнес-процессы, задачи, планы обмена, отчеты, обработки, общие модули, задания,
подписки, HTTP/Web-сервисы, определяемые типы, функциональные опции, последовательности, критерии,
нумераторы, хранилища настроек, общие формы/команды/реквизиты/картинки/макеты и внешние источники.

Поддержка типа скриптом означает корректное полное имя и ожидаемый каталог XML. Возможность создать
самодостаточный минимальный объект определяется reference-файлом `meta-compile` конкретного типа.
